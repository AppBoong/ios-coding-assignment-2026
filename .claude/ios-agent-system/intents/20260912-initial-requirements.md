# DummyJSON 상품 목록·상세·찜 앱 (iOS 개발자 사전 과제) 초기 구축

## 페인포인트 / 왜

- 채용 사전 과제. 심사 기준은 UI 완성도가 아니라 **요구사항 해석과 구조 설계** — 원격/로컬 데이터 책임 구분, 상태 관리 구조, 비동기 처리가 코드에서 읽혀야 한다.
- 제출은 fork 레포의 PR. PR 본문에 설계 설명·기술 판단·개선점·AI 활용 내역을 써야 하므로, 구현 중 내린 결정을 AUDIT에 남겨 PR 작성 재료로 쓴다.
- 수행 시간 1일 — 과도한 기능·폴리싱보다 요구사항을 빠짐없이, 구조가 드러나게 구현하는 것이 우선.

## 성공 기준 (관찰 가능한 문장)

1. **상품 목록**: 앱 실행 시 `GET https://dummyjson.com/products?limit=20&skip=0`으로 첫 페이지를 받아 각 셀에 상품명·가격·상품 이미지·찜 여부를 표시한다.
2. **페이지네이션**: 20개씩 로드한다. 마지막으로 로드된 페이지의 16번째 아이템이 화면에 나타나면 다음 페이지(`skip += 20`)를 요청한다. 스크롤을 반복하거나 셀이 여러 번 나타나도 같은 페이지 요청은 1회만 나간다(로딩 중 재요청 금지). `total`에 도달하면 더 요청하지 않는다.
3. **풀투리프레시**: 목록을 당겨서 새로고침하면 `skip=0`부터 다시 받아 기존 목록을 교체한다. 찜 상태는 로컬 값이므로 유지된다.
4. **보기 방식 전환**: 툴바 토글로 1열(리스트형)/2열(그리드형)을 전환한다. 전환해도 표시 정보 4가지(상품명·가격·이미지·찜 여부)와 이미 로드된 페이지는 동일하게 유지된다. 선택한 보기 방식은 로컬(UserDefaults)에 저장돼 앱 재실행 후에도 유지된다.
5. **찜 토글**: 목록 셀과 상세 화면 양쪽에서 찜/해제할 수 있다. 서버 API를 쓰지 않고 로컬(UserDefaults)에 저장하며, 앱을 종료 후 재실행해도 유지된다.
6. **찜 동기화**: 상세에서 찜을 바꾸고 목록으로 돌아오면 목록 셀에 즉시 반영된다(반대 방향도 동일). 단일 소스(공유 FavoriteRepository)가 상태를 방송한다.
7. **상품 상세**: 셀을 탭하면 상세로 이동하고, 진입 시 `GET https://dummyjson.com/products/{id}`를 호출해 주요 정보(이미지, 상품명, 가격, 할인율, 브랜드, 카테고리, 평점, 재고, 설명)를 표시하며 찜 토글이 있다.
8. **에러 처리**: 첫 페이지/상세 로드 실패 시 한국어 에러 메시지와 재시도 버튼을 보인다. 다음 페이지 로드 실패 시 기존 목록은 유지하고 하단에서 재시도할 수 있다.
9. **빌드 조건**: clone 후 Xcode 26.5로 `JGNR-HW.xcodeproj`를 열어 추가 작업 없이 시뮬레이터에서 빌드·실행된다. 외부 의존성 0.
10. **테스트**: 핵심 도메인·뷰모델(페이지네이션 중복 방지, 찜 토글·영속·동기화, 상세 로드)을 Swift Testing으로 검증한다.

## 제약

- Xcode 26.5 · Swift 6 language mode · strict concurrency complete · 기본 actor isolation `nonisolated`(격리는 명시적으로)
- SwiftUI 전용, iOS 17.0+ 안정 API만 (iOS 26 신규 API 사용 안 함)
- 외부 라이브러리 없음 — URLSession · UserDefaults · 자체 이미지 캐시
- 단일 xcodeproj, MVVM-C + Clean(Presentation / Domain(UseCase) / Data / Shared 인프라), Swift Concurrency, 수동 이니셜라이저 주입
